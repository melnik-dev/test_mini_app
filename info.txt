Общие правила по архитектуре и стилизации проекта
Темизация и стилизация
Используйте единообразную систему цветовых переменных CSS через пресет Tgm.js и Tailwind CSS. Все цвета интерфейса всегда берутся из CSS-переменных.

Для тёмной и светлой темы задавайте классы .dark только на корневом элементе (html или body).

Стили компонентов (PrimeVue, Tailwind) пишите через семантические классы: bg-surface-0, text-surface-900, text-primary, а не через жёсткие цвета.

Для кастомных компонентов и оберток используйте комбинации классов bg-surface-0 dark:bg-surface-900 и text-surface-900 dark:text-surface-0, чтобы обеспечить автоматическое переключение темы.

Никогда не пишите дублирующиеся стили с tailwind dark: непосредственно, если можно обойтись за счёт CSS-переменных.

В проекте используйте стандартные компоненты PrimeVue с кастомным пресетом (Tgm.js) для максимальной консистентности.

Организация компонентов
Компоненты должны быть максимально децентрализованы и управляться через пропсы и события.

Используйте v-model и реактивное состояние через ref и computed для управления состояниями.

Все повторяющиеся UI элементы (кнопки, табы, модалки) создаются как отдельные переиспользуемые компоненты с готовой стилизацией.

Используйте промты для описания каждого компонента, чтобы можно было быстро сгенерировать код или документацию.

Состояния и события
Взаимодействие с модалками и подтверждениями только через официальные PrimeVue сервисы (useConfirm и ConfirmDialog).

Для всех жестких действий (удаление, сохранение и т.п.) используйте централизованные методы и приложения toast уведомления для UX.

Избегайте ручного управления видимостью модалок через v-if — используйте сервисы PrimeVue.

Tailwind CSS и Pug
Писать классы с точками для Tailwind в Pug следует через атрибуты class="py-1.5 px-4 ...", чтобы избежать ошибок парсера.

Используйте только tailwind классы с поддержкой JIT компилятора.

Классы должны строго следовать семантике из темы, избегайте хардкода цветов.

Theme Switch
Переключение тёмной/светлой темы всегда по корневому классу .dark.

Для локальной разработки и отладки храните настройку темы в localStorage, в проде полагайтесь на Telegram Web App API.

Инициализировать тему нужно программно сразу при загрузке приложения, чтобы избежать мерцания.

Документация и промты
Для каждого компонента храните описание его API, назначение, пропсы и важные особенности.

Обучите промты поддерживать шаблоны для быстрой генерации компонентов с правильной темизацией и семантикой.

Используйте комментарии в коде с примерами вызовов и особенностями.
